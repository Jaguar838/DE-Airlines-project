## Этап 1: Настройка облачной инфраструктуры (IaC с Terraform)

На этом этапе мы используем Terraform для автоматического создания необходимых ресурсов в Google Cloud Platform (GCP).

### Предварительные требования

1.  **Установленный Terraform:** [Инструкция по установке](https://learn.hashicorp.com/tutorials/terraform/install-cli)
2.  **Установленный Google Cloud SDK:** [Инструкция по установке](https://cloud.google.com/sdk/docs/install)
3.  **Аккаунт в GCP** с созданными проектом и правами на создание ресурсов.
Загрузка файлов в GCS и работа с BigQuery сервисному аккаунту понадобятся две основные роли:
Storage Object Admin — чтобы записывать файлы в бакет.
BigQuery Data Editor — чтобы загружать данные в таблицы.


### Шаги по настройке и развертыванию

1.  **Конфигурация проекта**

    Файл `main.tf` в корне проекта содержит описание всех необходимых ресурсов. По умолчанию он создает:
    *   Бакет в Google Cloud Storage (GCS) для использования в качестве озера данных (Data Lake).
    *   Набор данных (Dataset) в BigQuery для использования в качестве хранилища данных (Data Warehouse).

    Перед применением конфигурации, откройте файл `main.tf` и **замените** значение по умолчанию для переменной `project_id` на ваш реальный ID проекта в GCP.

    ```terraform
    variable "project_id" {
      description = "Your GCP Project ID"
      default     = "ваш-реальный-id-проекта" // <--- ЗАМЕНИТЕ ЭТО
      type        = string
    }
    ```

2.  **Аутентификация в GCP**

    Выполните в вашем терминале следующую команду и следуйте инструкциям в браузере для аутентификации:
    ```bash
    gcloud auth application-default login
    ```

## Этап 2: Автоматизация конвейера данных (Оркестрация с Kestra)

На этом этапе мы используем Kestra для создания автоматизированного конвейера, который извлекает локальные данные, загружает их в облако и запускает трансформации dbt.

### Предварительные требования

1.  **Установленный Docker** и **Docker Compose**.
2.  **Kestra**, запущенная локально. Вы можете использовать `docker-compose.yml` из официального репозитория Kestra для быстрого старта.

### Описание потока

Потоки оркестрации находятся в папке `kestra/flows`: 
- `ingest_airlines_data_prod.yml` отвечает за извлечение данных из архивов и загрузку в GCS. 
- `airline_full_load_bq.yml` отвечает за загрузку данных из GCS в BigQuery.
- `airline_dbt_bigquery_transformation_dev.yml` отвечает за трансформации dbt в режиме разработки.
- `airline_dbt_bigquery_transformation_prod.yml` отвечает за трансформации dbt в режиме производства.

### Как запустить

1.  Убедитесь, что Kestra запущена.
2.  Перейдите в веб-интерфейс Kestra.
3.  Создайте новое пространство имен (namespace), если это необходимо.
4.  Загрузите и выполните потоки из папки `kestra/flows`.
Начните с `ingest_airlines_data_prod.yml`, чтобы загрузить данные в GCS, а затем используйте `airline_full_load_bq.yml` для их обработки.

## Этап 3: Трансформация данных (dbt)

На этом этапе мы используем dbt (Data Build Tool) для преобразования "сырых" данных, загруженных в BigQuery, в готовые к анализу витрины данных. Мы также настроим dbt для работы с вашим GCP проектом.

### Предварительные требования

1.  **Установленный dbt-core и dbt-bigquery:**
    ```bash
    pip install dbt-core dbt-bigquery
    ```
2.  **Данные, загруженные в BigQuery** (выполнен Этап 2).

### Настройка подключения (`profiles.yml`)

`dbt` узнает, как подключаться к вашему хранилищу данных, из файла `profiles.yml`. Обычно этот файл находится в `~/.dbt/`.

1.  **Создайте файл `profiles.yml`** со следующим содержимым (убедитесь, что имя профиля `de-project-dbt` совпадает с `profile` в вашем `dbt_project.yml`):

    ```yaml
    de-project-dbt: 
      target: dev
      outputs:
        dev:
          type: bigquery
          method: application-default
          project: "{{ env_var('GCP_PROJECT_ID') }}"
          dataset: "{{ env_var('GCP_DATASET') }}"
          threads: 4
          location: EU
    ```

2.  **Установите переменные окружения:** Перед запуском dbt убедитесь, что вы установили переменные, определенные на Этапе 1.

    ```bash
    export GCP_PROJECT_ID="ваш-реальный-id-проекта"
    export GCP_DATASET="имя-вашего-dataset"
    ```

### Запуск моделей dbt

После настройки `profiles.yml` вы можете запустить все трансформации. Перейдите в папку `dbt/` и выполните следующие команды:

1.  **`dbt deps`**
    *Устанавливает все необходимые зависимости для проекта.*
    ```bash
    dbt deps
    ```

2.  **`dbt seed`**
    *Загружает справочные данные (например, `aircrafts`, `airports`) из CSV-файлов в папке `seeds/` в BigQuery.*
    ```bash
    dbt seed
    ```

3.  **`dbt run`**
    *Запускает все модели. При первом запуске он создаст все таблицы. При последующих запусках инкрементальные модели (такие как `fct_flights`) будут обновляться только новыми данными.*
    ```bash
    dbt run
    ```

4.  **`dbt test`**
    *Выполняет все тесты данных, определенные в `.yml` файлах, чтобы убедиться в качестве и целостности данных.*
    ```bash
    dbt test
    ```

### Результат

После успешного выполнения этих команд в вашем BigQuery появятся очищенные, структурированные таблицы и витрины данных, готовые для анализа и визуализации на следующем этапе.
